## 1. Что это

**oheedet** — снижение веса **без спортзала**, только питанием и образом жизни, на
подтверждённой науке. Продукт — **PWA**, которое собирает персональное недельное меню
(что есть, сколько, когда) под условия человека: аллергии, нелюбимая еда, посуда/техника,
бюджет, кухни мира, режим «на двоих» (пользователь + партнёр).

**Честная рамка (D-001):** никаких «жиросжигающих продуктов». Единственный механизм —
**дефицит энергии**; всё остальное (белок, клетчатка, плотность калорий, сон, среда) —
рычаги, которые делают дефицит **незаметным и удерживаемым**.

**Продуктовая цель (важно):** доказать, что питание для похудения бывает **вкусным**.
Рецепты писались под это: флейвор-бомбы (гочжан, харисса, мисо, карри), умами, маринады,
кремовые соусы без сливок.

## 5. Приложение: как устроено

**Стек (осознанно ленивый):** vanilla ES-модули, **ноль зависимостей, ноль сборки**,
тесты на встроенном `node --test`. PWA без бэкенда.

```
app/
  index.html      онбординг-форма (хинты, SCOFF-вопросы, кухни, партнёр, 13 пунктов техники)
  app.js          оркестрация: профиль → цели → safety → план → покупки → рендер; регистрация SW
  render.js       меню с кнопками замены, модалка рецепта, покупки по дням, покупное сладкое
  tracker.js      отметки «съел по плану» + вес; SVG-график динамики + приверженность
  tokens.css      ДИЗАЙН-ТОКЕНЫ (индиго #5E6AD2, свет/тьма)
  styles.css      компоненты через токены
  manifest.json   PWA-манифест       icons/  иконки 192/512 (+maskable)
  sw.js           service worker (офлайн, cache-first). ВАЖНО: бампать CACHE при изменении статики
  data/recipes.json  36 рецептов     data/treats.json  8 покупных лакомств
  src/targets.js  TDEE (Mifflin-St Jeor) → калории/белок/клетчатка/темп
  src/safety.js   guardrails: пол калорий, скрининг → «к врачу», смягчение дефицита
  src/planner.js  фильтры + генерация дня/недели + swapDish (замена блюда)
  src/couple.js   режим «на двоих» (общий ужин, порции под каждого)
  src/grocery.js  список покупок: по дням, скоропорт, ₽; канонизация имён (без дублей)
  test/*.test.js  19 тестов
```

## 6. Логика движка (что зашито)

**Цели (`targets.js`):** Mifflin-St Jeor → BMR; ×коэффициент активности (low 1.2 / medium 1.375 /
high 1.55) → TDEE; дефицит 550 ккал/д; белок 1.6 г/кг (реф-вес); клетчатка 30 г; темп ≤1 кг/нед.

**Безопасность (`safety.js`):** пол калорий 1200 (ж) / 1500 (м); флаги скрининга
(щитовидка / СПКЯ / психотропные / SCOFF ≥2) → `referDoctor`, дефицит смягчается до TDEE−300,
показывается баннер «обсуди с врачом».

**План дня (`planner.js`):**
- Слоты: завтрак 08:00 / обед 13:00 / **десерт 16:00** / ужин 18:00.
- Распределение 30/40/30 от (цель − бюджет лакомства), **лакомство = 12% калорий** — десерт
  вписан в норму, поэтому сладкое не ломает дефицит.
- **Добор белка:** идёт в самое белково-**плотное** блюдо и не раздувает день выше **+8%** цели.
  (Раньше лил в самое белковое по абсолюту — день раздувался до +35%. Это был баг, исправлен.)
- **Бюджет** — потолок цены порции: small 205 ₽ / medium 270 ₽ / large ∞.
- **Кухня** — мягкий фильтр: `universal` проходит всегда, поэтому план никогда не пустеет.
- `swapDish()` — замена блюда на следующее в том же слоте с сохранением доли калорий.

**Пара (`couple.js`):** два реальных профиля; общий ужин (готовите один раз), порции под каждого.
Пул рецептов — по **объединению** аллергий/нелюбимого обоих, чтобы общий ужин подошёл каждому.

**Покупки (`grocery.js`):** канонизация имён (`имя|единица` в нижнем регистре) — поэтому нет
дублей «яйцо/яйца»; группировка **по дням**; пометка скоропорта (свежие категории, кроме
консервов/заморозки/сушёного); цена в ₽ по дню и за неделю.

## 7. Честные факты, выясненные замерами (не выдумывать заново)

- **Бюджет почти не меняет ₽/день.** При фиксированной цели по белку выходит **~760–800 ₽/день**
  на любом уровне: объём продуктов задаёт белок, а уровень меняет **набор блюд** (курица/крупы
  против лосося/говядины). Это прямо написано в UI — занижать цифры было бы враньём.
- **Разброс калорий по дням:** −2%…+9% от цели (после фикса добора белка).
- Цены `cost_rub` в рецептах — **прикидка**, под реальный магазин не калибровались.

## 8. Решения (полностью — в DECISIONS.md)

- **D-001** Честная рамка: только дефицит, никаких чудо-продуктов.
- **D-003** Фокус — питание и образ жизни, без спортзала.
- **D-004** Только peer-reviewed, иерархия доказательности.
- **D-005** Безопасность — часть продукта.
- **D-006** Объём MVP: ядро = генератор недельного меню. **В v2:** дневник/сканер, гликемическая
  персонализация, **интеграция сна (стык с pospat)**, GLP-1, аккаунты.
- **D-007** Платформа — **PWA** (Telegram-бот отклонён).
- **D-008** v1 без ручного подсчёта калорий (трекинг-лайт «съел/заменил» + вес).

## 9. Наука в одном экране (детали — findings.md)

- **Единственный механизм — дефицит.** При равных калориях тип диеты почти не влияет `[S-001, S-003]`.
  Решает **приверженность** `[S-006…S-009]`.
- **Почему «без спорта» работает:** тело компенсирует нагрузку (~30% от ожидаемого прироста
  расхода) `[S-004]`; питанием дефицит создаётся легко.
- **Сытость без подсчёта:** белок 1.2–1.6 г/кг `[S-012, S-013]`; клетчатка ≥30 г `[S-015]`; низкая
  калорийная плотность `[S-017, S-018]`; минимум ультра-переработки (+508 ккал/д скрыто) `[S-016]`;
  долой жидкие сахара `[S-019, S-020]`.
- **Вне тарелки:** сон (недосып +253 ккал/д; продление сна −270 ккал/д) `[S-031, S-032]`;
  порции/посуда (±12–16%) `[S-040]`; вода перед едой `[S-036, S-037]`; алкоголь `[S-038]`; стресс `[S-033]`.
- **Тайминг:** IF не лучше обычного дефицита `[S-022, S-023]`; завтрак необязателен `[S-025]`;
  **поздняя еда реально мешает** `[S-026]`.
- **Поведение:** трекинг — самый доказанный рычаг `[S-041, S-042]`; привычки «если-то» `[S-043]`.
- **Откат:** гормоны голода после похудения год не возвращаются `[S-045]`; удерживают режим +
  мониторинг `[S-049]`.
- **Безопасность:** темп 0.5–1 кг/нед, не VLCD `[S-052]`; скрининг лекарств/состояний `[S-055]` и
  РПП `[S-058, S-059]`.
- **Мифы (не обещаем):** detox, «разгон метаболизма», спот-редукция, БАДы `[S-061…S-065]`.

## 10. Известные ограничения и «долги»

- **Замена блюд в режиме пары отключена** (общий ужин усложняет) — только соло.
- **`ponytail:`-пометки в коде** (осознанные упрощения с названным потолком):
  - `planner.js` — жадный набор + добор белка; при систематическом промахе → оптимизатор (ILP).
  - `planner.js` — стемминг «нелюбимого» обрезкой окончания (ловит капуста→капустой), не морфология.
  - `couple.js` — делится только ужин.
  - `render.js` — замена только в соло-режиме.
- **`costTier` у ингредиентов** — мёртвое поле (цена теперь через `recipe.cost_rub`), чистить лень.
- **Иконки `↻`, `🕒`** — глифы вместо SVG (осознанный размен: ноль зависимостей).
- **Нет автотестов на DOM** (накопление слушателей, пустой экран) — проверялось замерами в браузере;
  jsdom не тянули ради пары случаев.
- **Источники с пометкой `Note:`** в sources.md требуют сверки DOI/авторов перед публичным использованием.

### Грабли, на которые уже наступали (не повторять)

1. **Накопление слушателей.** `#result` переживает перерисовку (меняется только `innerHTML`).
   Вешать на него `addEventListener` в `renderResult` = обработчики удваиваются с каждой заменой
   (1→2→4→8), приложение виснет. Используется `el.onclick =` — **не менять обратно**.
2. **Пустой экран после обновления.** Старое состояние в localStorage ломало `renderResult`.
   Восстановление сессии обёрнуто в try/catch со сбросом состояния — **не убирать**.
3. **SW-кэш.** При изменении статики бампать `CACHE` в `sw.js` (сейчас `oheedet-v6`), иначе у
   установленных останется старая версия.
4. **Скриншот-пейн preview** вешается на прокрутке длинной страницы — низ страницы проверять
   структурно через JS, а не картинкой.
